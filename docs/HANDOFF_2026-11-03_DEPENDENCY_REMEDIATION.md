## Evidence

The current main branch lockfile returned six advisory packages on the GitHub runner on 3 November 2026:
- Production dependency graph: `body-parser` 2.3.0 (high), `fast-uri` 3.1.8 (moderate), `qs` 6.16.0 (moderate).
- Development dependency graph: `undici` 7.29.1 (high), with `miniflare` and `wrangler` also reported as dependents in the audit results.
- Full audit counts: 4 moderate, 2 high. Production-graph counts: 2 moderate, 1 high. These results do **not** prove the vulnerable Node packages are in the deployed Cloudflare Worker bundle.

The original audit: GitHub Actions [41727815327](https://github.com/GSGrimoire/gs-poster/actions/runs/41727815327). Prior review of an older bundle reported the production-graph packages were not bundled. That claim still needs verification for this final source and build.

## Exact corrective dependency versions

- `body-parser` 2.3.0 to **2.4.0**, patched for compressed request body trailing-byte denial of service.
- `fast-uri` 3.1.8 to **3.1.9**, patched for URI host/scheme normalization advisories.
- `qs` 6.16.0 to **6.17.1**, beyond the 6.16.1 patched version for comma-join stringification.
- `undici` 7.29.1 to **7.30.1**, patched for the reported Node HTTP client issues.

The exact package metadata, dependency requirements, resolved tarball URLs and integrity digests were generated by `npm install --package-lock-only --ignore-scripts` on a GitHub-hosted Node 22 runner, not hand-invented. The candidate `npm ci --ignore-scripts` and both audits passed before those package-lock entries were applied. The temporary lockfile-generation workflow step was removed afterwards.

A limited `overrides` object in package.json prevents npm from choosing the older vulnerable transitive releases on a future clean installation. No direct application dependency, publishing code, OAuth, user credentials or deployment workflow changes. No `npm audit fix --force`.

## Ongoing detection and failure behavior

`.github/workflows/dependency-audit.yml` schedules a Monday audit and supports manual dispatch and dependency-related pull requests. The read-only job checks out source, runs `npm ci --ignore-scripts`, and executes both `npm audit --json` and `npm audit --json --omit=dev` using `scripts/audit-dependencies.mjs`.
- The summary distinguishes full and production dependency graphs and reports direct/transitive status and advisory titles.
- A full structured JSON report is retained as a workflow artifact.
- If the audit tool fails or returns malformed JSON, the job fails rather than claiming the tree is safe.
- A high/critical production dependency advisory fails the audit job. Other advisories are still reported for independent evaluation.
- Scheduled audit does not modify dependencies, trigger deployment or require Cloudflare secrets. Artifacts contain public dependency metadata only.

## Full-review checklist

Inspect package-lock metadata and npm overrides against upstream patch availability, `npm ci` reproducibility, whether `undici` 7.30.1 works with the pinned Miniflare beta and Wrangler, test regressions, supply-chain provenance, `scripts/audit-dependencies.mjs` failure handling, checkout and report permissions, and whether any HTTP/body parser is actually included in the Cloudflare Worker bundle. Confirm no new exposure of secret material, no new publishing permission and no changes to authenticated server-side request-fencing paths.

Use the final exact-head GitHub Actions run as evidence, not the earlier candidate-generation run. A zero-advisory report is a database-based snapshot, not a guarantee against undisclosed vulnerabilities or real provider integration failures. No live-site testing or deployment is performed by this PR.
